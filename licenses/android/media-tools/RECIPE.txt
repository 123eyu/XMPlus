XMPlus Android media executable recipe

Scope and artifact identity
---------------------------
This application builds its own FFmpeg and FFprobe command-line executables
from the exact source archives locked in tool/media_sources.json. It does not
use FFmpegKit, download executable binaries, or call a JNI FFmpeg library.
The names libxmplus_ffmpeg.so and libxmplus_ffprobe.so are Android packaging
names for PIE command-line executables, not shared-library entry points.

Android supplies the public NDK runtime libraries libc, libm, libdl and libz.
They are platform prerequisites, not additional libraries copied into the APK.

to be a separately distributed static dependency. Exact DT_NEEDED entries are
recorded by llvm-readelf for each generated executable. Page-size claims for
our executables do not assert anything about a device's platform libraries.

Build command
-------------
Use Linux x86_64, Bash, make, tar, jq, sha256sum and the Android NDK
28.2.13676358 toolchain. Install nasm for the x86_64 FFmpeg assembler.
Set ANDROID_NDK_HOME to that NDK, or set ANDROID_HOME to an SDK containing it.
No SDK license terms are accepted by this script.

  bash tool/build_android_media.sh
  bash tool/build_android_media.sh arm64-v8a
  bash tool/build_android_media.sh armeabi-v7a
  bash tool/build_android_media.sh x86_64

JOBS overrides make parallelism. SOURCE_ROOT may point to another checkout/root
containing tool/media_sources.json and its relative archive paths. There is no
network fetching or unverified fallback. Every invocation hashes its archives
and extracts fresh copies into build/android-media/sources before compiling.

Configuration
-------------
Targets: arm64-v8a, armeabi-v7a and x86_64, Android API 24, NDK r28c clang.
FFmpeg and LAME libraries are static inside each PIE executable. The recipe
uses -fPIE/-pie and maximum/common ELF page sizes of 16384. Platform runtime
libraries remain dynamic. Original configure scripts, exact configure command
arguments, generated config.h/config_components.h, config.log, output SHA-256,
source lock and ELF headers/program headers/dynamic entries are retained in:

  build/android-media/<abi>/receipt/
  build/android-media/media_sources.json

The recipe disables external-library autodetection, FFplay, device IO, docs,
debug information and network protocols. Only file and pipe protocols remain.
Starting with --disable-everything, the recipe explicitly enables the audio
decoders/encoders, PCM integer/float bit depths, parsers, remux containers,
hash/null muxers, AAC bitstream filter and audio conversion filters required by
MediaProcessor. Image inputs are image2/image2pipe/image_png_pipe/image_jpeg_pipe;
the latter two are FFmpeg 9 configure names, not the shorter runtime names.
FFmpeg also selects its required core graph helper filters. Explicit external
features are libmp3lame and Android system zlib. AAC/MP3/M4A/M4B/ALAC/FLAC,
Ogg Vorbis/Opus and WAV input, MP3/AAC/FLAC output, original stream copying,
aac_adtstoasc, SHA-256 packet hashing, null decode, PCM/format conversion,
PNG/JPEG cover decode, attached pictures and container metadata remain within
the configuration. Actual runtime capabilities require execution on Android;
this recipe itself is not runtime smoke evidence.

Installation and execution
--------------------------
Output paths are android/app/src/main/jniLibs/<abi>/libxmplus_{ffmpeg,ffprobe}.so.
Gradle requires both nonempty files for each requested target ABI before
preBuild; missing tools must fail a build, not create a misleading APK.
Legacy native packaging and extractNativeLibs request installer extraction.
MainActivity returns only canonical executable paths in the application's
nativeLibraryDir. Dart validates the absolute directory and exact child file
paths before using the existing bounded, cancellable Process runner. Tools
are never copied to writable filesDir/cache for execution. Android ignores
restored desktop tool overrides; Windows retains its existing path behavior.

Build and runtime evidence
--------------------------
The build manifest describes the selected recipe and source/output hashes;
it does not independently prove successful Android installation or runtime
behavior. Release acceptance must inspect the actual packaged ELF files and
run the production MediaProcessor on Android, including conversion, original
packet hash, covers, cancellation and prepayment prevention when tools fail.
